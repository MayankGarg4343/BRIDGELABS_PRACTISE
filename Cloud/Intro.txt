2. STAGE 1: PHYSICAL SERVERS
============================================================

QUESTION:
How did applications run traditionally?

ANSWER:
Applications ran directly on physical hardware.

ARCHITECTURE:

+--------------------------------------+
|            Application               |
+--------------------------------------+
|          Operating System            |
+--------------------------------------+
|          Physical Server             |
|                                      |
| CPU | RAM | Disk | Network           |
+--------------------------------------+

Example:

Company buys one powerful server:

CPU Usage = 10%
RAM Usage = 20%

But the company still pays for:

- Full server
- Electricity
- Cooling
- Rack space
- Hardware maintenance
- Replacement parts

QUESTION:
What is the main problem here?

ANSWER:
POOR HARDWARE UTILIZATION.

You buy 100% of the server but may use only 10-20% of it.

============================================================
4. STAGE 2: VIRTUALIZATION
============================================================

Virtualization allows physical computing resources to be divided
into multiple isolated virtual environments.

ARCHITECTURE:

+------------------------------------------------+
|                     VM 1                       |
| App + OS + vCPU + vRAM + Virtual Disk          |
+------------------------------------------------+

+------------------------------------------------+
|                     VM 2                       |
| App + OS + vCPU + vRAM + Virtual Disk          |
+------------------------------------------------+

+------------------------------------------------+
|                     VM 3                       |
| App + OS + vCPU + vRAM + Virtual Disk          |
+------------------------------------------------+

+================================================+
|                  HYPERVISOR                    |
+================================================+
|               PHYSICAL HARDWARE                |
|       CPU | RAM | Disk | NIC                   |
+================================================+


QUESTION:
What does the Hypervisor do?

ANSWER:
It sits between the physical hardware and Virtual Machines.

Its job is to:

- Abstract physical hardware
- Create Virtual Machines
- Allocate CPU
- Allocate RAM
- Allocate Storage
- Manage virtual networking
- Provide isolation between VMs


HYPERVISOR EXAMPLES:

1. VMware ESXi
2. Microsoft Hyper-V
3. KVM


============================================================
5. WHAT DOES A VM HAVE?
============================================================

A Virtual Machine can have:

+------------------------+
|         VM             |
+------------------------+
| vCPU                   |
| vRAM                   |
| Virtual Disk           |
| Virtual NIC            |
| Operating System       |
| Applications           |
+------------------------+


IMPORTANT:

vCPU != Physical CPU directly
vRAM != Physical RAM directly

The Hypervisor abstracts and manages physical resources.

6. BENEFITS OF VIRTUALIZATION
============================================================

BEFORE:

1 Physical Server
        |
        v
1 Workload


AFTER:

1 Physical Server
        |
        v
Hypervisor
   /    |    \
 VM1   VM2   VM3


BENEFITS:

[+] Better hardware utilization
[+] Multiple workloads on one physical server
[+] Faster provisioning
[+] Workload isolation
[+] Flexible resource allocation


QUESTION:
Does Virtualization = Cloud Computing?

ANSWER:
NO.

IMPORTANT CONCEPT:

Virtualization = Technology

Cloud Computing = Broader delivery and operating model


MEMORY TRICK:

Virtualization tells you:
"HOW resources can be abstracted."

Cloud tells you:
"HOW resources are delivered, managed and consumed."

7. STAGE 3: PRIVATE CLOUD
============================================================

Private Cloud means:

A cloud environment dedicated to ONE organization.

Example:

+----------------------------------+
|         COMPANY PRIVATE CLOUD    |
|                                  |
|  Compute | Storage | Networking  |
|                                  |
|  Self-Service Portal             |
|  APIs                             |
|  Automation                      |
+----------------------------------+

            Only Company


PRIVATE CLOUD CAN PROVIDE:

[+] Self-service
[+] Automation
[+] APIs
[+] Resource abstraction
[+] Centralized management


QUESTION:
Is Private Cloud always easy to manage?

ANSWER:
No.

The company may still need to manage:

- Hardware
- Capacity
- Networking
- Security
- Data center operations
- Maintenance


LIMITATIONS:

1. Capacity limits
2. Hardware investment
3. Operational burden
4. Global expansion is difficult


Example:

Company needs 100 servers today.

But next month it needs 1,000 servers.

QUESTION:
Can the company instantly get 1,000 physical servers?

ANSWER:
Usually no.

They need capacity planning and additional infrastructure.

8. STAGE 4: PUBLIC CLOUD
============================================================

Public Cloud providers operate massive infrastructure and
deliver services to customers.

MAJOR PROVIDERS:

12. AUTHENTICATION vs AUTHORIZATION
============================================================

AUTHENTICATION:

"Who are you?"

Example:

Username + Password
MFA
Access Token


AUTHORIZATION:

"What are you allowed to do?"

Example:

User A:
Can create VM

User B:
Can only view VM


MEMORY TRICK:

Authentication = Identity

Authorization = Permission

============================================================

Infrastructure configuration is written and managed as code.

- Bicep


Example concept:

"I need 3 VMs."

19. TROUBLESHOOTING CONCEPT
============================================================

QUESTION:

"We are using Virtualization, so why is provisioning still slow?"

IMPORTANT ANSWER:

Virtualization alone does NOT guarantee automation.


Provisioning can still be slow because of:

- Manual approvals
- Network configuration
- IP address allocation
- Security approval process
- Capacity limitations
- Manual OS configuration
- Manual application setup
- Lack of automation


EXAMPLE:

VM creation = 5 minutes

But approval process = 3 days

QUESTION:
Is the total provisioning process fast?

ANSWER:
NO.


THE BOTTLENECK MAY NOT BE THE VM.

Application directly runs on hardware.

Manages and abstracts physical resources for VMs.

Cloud features dedicated to one organization.

On-demand cloud services provided by large cloud providers.

API:
Allows software/programs to interact with cloud services.
