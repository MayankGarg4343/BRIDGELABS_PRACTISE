LINUX COMMAND NOTES – Filesystem Attributes (Advanced chattr & lsattr)

1. OVERVIEW

Filesystem attributes are special metadata flags stored in the
filesystem (mainly ext2/ext3/ext4). They work in addition to normal
Linux permissions (chmod/chown) and ACLs.

Commands: lsattr -> View attributes chattr -> Modify attributes

Why they are used: - Protect critical files from modification. - Prevent
accidental deletion. - Secure log files. - Harden Linux systems.

Problem they solve: Even if file permissions allow an operation,
filesystem attributes can prevent it. They provide an extra layer of
protection.

  --------------------------------------------------
  2. COMMON ATTRIBUTES
  --------------------------------------------------
  i Immutable Cannot modify, rename, delete or
  hard-link the file.

  a Append-only Existing data cannot be changed; new
  data may only be appended.

  A No atime updates Reduces access-time updates.

  d Exclude from dump backups.

  e Extent-based storage (common on ext4).

  j Data journaling.

  s Secure deletion (filesystem support dependent).

  u Undelete information (filesystem support
  dependent).
  --------------------------------------------------

3. VIEW & MODIFY

View: lsattr file

Set immutable: chattr +i file

Remove immutable: chattr -i file

Set append-only: chattr +a logfile

Recursive: chattr -R +i directory

  --------------------------------------------------
  4. ATTRIBUTE PRECEDENCE
  --------------------------------------------------
  Filesystem Attributes ↓ ACLs ↓ Traditional
  Permissions (chmod)

  Example: A file with 777 permissions and +i cannot
  be edited until the immutable attribute is
  removed.
  --------------------------------------------------

5. REAL-WORLD USE CASES

• Protect /etc/passwd from accidental modification. • Make audit logs
append-only. • Lock application configuration after deployment. •
Protect backup archives. • Investigate “Operation not permitted” errors.

  --------------------------------------------------
  6. TROUBLESHOOTING
  --------------------------------------------------
  Problem: Cannot delete file.

  Check: lsattr file

  Cause: Immutable (+i)

  Fix: sudo chattr -i file

  Problem: Application cannot overwrite a log.

  Cause: Append-only (+a)

  Fix: Remove +a temporarily if overwrite is
  required.
  --------------------------------------------------

7. SECURITY BEST PRACTICES

-   Apply +i only to critical files.
-   Use +a for logs.
-   Audit attributes regularly.
-   Document attribute changes.
-   Verify after changes with lsattr.

  --------------------------------------------------
  8. chattr vs chmod vs ACL
  --------------------------------------------------
  chmod Controls read/write/execute permissions.

  ACL Fine-grained user/group permissions.

  chattr Filesystem-level protection and behavior.
  --------------------------------------------------

9. SCENARIO-BASED QUESTIONS

1.  A file has 777 permissions but cannot be deleted. Answer: Check for
    the immutable attribute using lsattr.

2.  Which command removes immutable protection? Answer: chattr -i file

3.  Which attribute is recommended for audit logs? Answer: +a
    (append-only)

4.  Which command displays attributes? Answer: lsattr

5.  Which command modifies attributes? Answer: chattr

6.  Why can chmod fail to solve an access issue? Answer: Filesystem
    attributes or ACLs may override the expected behavior.

7.  What problem do filesystem attributes solve? Answer: They provide an
    additional protection layer beyond standard permissions.

8.  Which attribute prevents renaming? Answer: +i (immutable).

9.  When should +i be removed? Answer: Before updating or patching the
    protected file.

10. Which should be checked first when root gets “Operation not
    permitted”? Answer: Filesystem attributes using lsattr.

11. Which tools work together for advanced file protection? Answer:
    chmod, chown, setfacl/getfacl, chattr, and lsattr.
