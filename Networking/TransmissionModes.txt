TOPIC: Data Transmission Modes — Full Notes

1. BASIC DEFINITION

Data Transmission Mode batata hai ki do communicating devices ke beech data kis direction mein flow kar sakta hai.

Three major transmission modes:

1. Simplex
2. Half Duplex
3. Full Duplex


2. SIMPLEX

Definition:
- Data sirf ek direction mein flow karta hai.
- Sender data transmit karta hai.
- Receiver data receive karta hai.
- Receiver sender ko same communication system ke through reply nahi kar sakta.

Diagram:

    A ─────────────► B

    A = Sender
    B = Receiver

    Direction: A → B only

Examples:
- Traditional TV broadcasting
- Traditional radio broadcasting
- Public announcement systems
- Some one-way telemetry/broadcast systems

Analogy:
- TV station se TV receiver tak signal.
- Sender bol raha hai, receiver sirf sun raha hai.

Advantages:
- Simple design
- Low complexity
- One-way applications ke liye efficient
- Return channel ki zarurat nahi

Disadvantages:
- Receiver response nahi de sakta
- Feedback unavailable
- Error recovery difficult
- Acknowledgement possible nahi through same channel


3. HALF DUPLEX

Definition:
- Data dono directions mein flow kar sakta hai.
- Lekin ek time par sirf ek direction active hoti hai.
- Simultaneous transmission allowed nahi hota.

Diagram:

    A ─────────────► B

    OR

    A ◄───────────── B

    But not simultaneously.

Analogy:
- Walkie-talkie
- Dono log bol sakte hain, but ek time par ek.

Timeline:

    Time 1:
    A → B

    Time 2:
    B → A

    Time 3:
    A → B

Important:
- Half duplex = two-way communication
- But simultaneous nahi


4. HALF DUPLEX INTERNAL IDEA

Half-duplex system ko decide karna padta hai ki current time par kaun transmit karega.

Possible coordination mechanisms:
- Token passing
- Polling
- CSMA/CD
- CSMA/CA
- Protocol-specific turn-taking

Agar shared medium par A aur B simultaneously transmit kar dein:

    A ─────►
             X
    ◄───── B

Collision/interference ho sakta hai.


5. CSMA/CD

CSMA/CD:
Carrier Sense Multiple Access with Collision Detection

Historically shared/half-duplex Ethernet mein use hota tha.

Basic process:

1. Device medium ko sense karta hai.
2. Check karta hai medium busy hai ya free.
3. Free ho toh transmit karta hai.
4. Agar two devices simultaneously transmit kar dein:
   - Collision hoti hai.
5. Devices collision detect karte hain.
6. Backoff algorithm ke through random waiting time ke baad retransmit karte hain.

Important:
- CSMA/CD modern normal full-duplex switched Ethernet mein required nahi hai.
- Ye primarily legacy/shared half-duplex Ethernet ke context mein important hai.


6. FULL DUPLEX

Definition:
- Data dono directions mein simultaneously flow kar sakta hai.
- Dono devices same time transmit aur receive kar sakte hain.

Diagram:

    A ─────────────► B
    A ◄───────────── B

    Both directions simultaneously.

TX/RX mental model:

    A TX ─────────────► B RX
    A RX ◄───────────── B TX

Analogy:
- Telephone call
- Dono persons simultaneously bol aur sun sakte hain.


7. FULL DUPLEX ETHERNET

Modern switched Ethernet normally full duplex hota hai.

Diagram:

    PC
     |
     | Full Duplex Ethernet
     |
    Switch
     |
     | Full Duplex Ethernet
     |
   Server

Conceptually:

    PC TX ───────────────► Switch RX
    PC RX ◄─────────────── Switch TX

Advantages:
- Simultaneous bidirectional traffic
- Traditional collisions eliminated on full-duplex point-to-point link
- Better utilization for modern server workloads
- Suitable for high-performance networking


8. SIMPLEX VS HALF DUPLEX VS FULL DUPLEX

Simplex:
- One-way
- Simultaneous communication: No
- Receiver reply: No
- Example: traditional TV broadcast

Half Duplex:
- Two-way
- Simultaneous communication: No
- Receiver reply: Yes, but turn-by-turn
- Example: walkie-talkie

Full Duplex:
- Two-way
- Simultaneous communication: Yes
- Receiver reply: Yes
- Example: telephone, modern switched Ethernet


9. QUICK VISUALIZATION

Simplex:

    A ─────────────► B

    One direction only.


Half Duplex:

    A ─────────────► B

    OR

    A ◄───────────── B

    One direction at a time.


Full Duplex:

    A ─────────────► B
    A ◄───────────── B

    Both directions simultaneously.


10. BANDWIDTH CONCEPT

Suppose link speed = 1 Gbps.

Full duplex generally means:

    A → B = up to 1 Gbps
    B → A = up to 1 Gbps

Both directions can operate simultaneously.

It does NOT mean:

    A → B = 2 Gbps

Full duplex improves simultaneous bidirectional capacity, not automatically the one-direction link speed.

Actual throughput depends on:
- Protocol overhead
- Hardware
- Traffic
- Packet size
- Congestion
- Network conditions


11. DUPLEX MISMATCH

Duplex mismatch:
- Link ke two ends incompatible duplex modes mein operate kar rahe hain.

Example:

    PC:
    Full Duplex

    Switch:
    Half Duplex

Possible symptoms:
- Poor performance
- Packet loss
- Retransmissions
- CRC errors
- Late collisions
- Interface errors
- Low throughput
- Intermittent connectivity problems


12. LINUX COMMANDS

Check network interfaces:

    ip link

or:

    ip addr


Check speed and duplex:

    sudo ethtool eth0

Example relevant output:

    Speed: 1000Mb/s
    Duplex: Full
    Auto-negotiation: on
    Link detected: yes


For another interface:

    sudo ethtool ens33


Check interface statistics:

    ip -s link show ens33


Check NIC-specific statistics:

    sudo ethtool -S ens33


13. EXAMPLE OF SETTING SPEED/DUPLEX

Example:

    sudo ethtool -s eth0 speed 1000 duplex full autoneg off

Meaning:
- Speed = 1000 Mbps
- Duplex = Full
- Auto-negotiation = off

WARNING:
- Production environment mein blindly configuration change nahi karna.
- Switch side bhi compatible hona chahiye.
- NIC/driver capability check karni chahiye.
- Remote server par wrong configuration connectivity break kar sakti hai.
- Configuration reboot ke baad persist nahi bhi ho sakti.


14. AUTO-NEGOTIATION

Ethernet devices compatible link parameters negotiate kar sakte hain.

Concept:

    Device A                    Device B

    1000 Full                   1000 Full
    100 Full                    100 Full
    10 Full                     10 Full

                ↓

        Select compatible mode

                ↓

             1000 Full

Auto-negotiation can help determine:
- Speed
- Duplex
- Other supported PHY capabilities depending on technology


15. TRANSMISSION MODE VS PROTOCOL

Do not confuse these concepts.

Transmission mode:
- Describes direction of communication.

Protocol:
- Defines rules of communication.

Example stack:

    Application
         ↓
       HTTP
         ↓
        TCP
         ↓
         IP
         ↓
     Ethernet
         ↓
      Physical

Full Duplex is not:
- TCP
- IP
- HTTP
- Ethernet itself

Duplex is a communication characteristic of the underlying networking technology.


16. OSI CONNECTION

Duplex is mainly associated with Physical/Data Link level communication behavior.

Simplified stack:

    Application
         |
    Transport      TCP / UDP
         |
    Network        IP
         |
    Data Link      Ethernet
         |
    Physical       Electrical / Optical / Radio

Ethernet PHY/link operation deals with:
- Speed
- Duplex
- Physical signaling
- Link state


17. TCP CONNECTION

TCP provides bidirectional byte-stream communication.

Example:

    Client ─────────────► Server
             Request

    Client ◄───────────── Server
             Response

But:
- TCP and duplex mode are different concepts.
- TCP is a transport-layer protocol.
- Duplex describes lower-level communication behavior.

TCP being bidirectional does not mean TCP itself defines Ethernet duplex.

20. MONITORING/TROUBLESHOOTING

If network is unexpectedly slow:

Step 1:
    ip link

Step 2:
    sudo ethtool eth0

Check:
- Speed
- Duplex
- Auto-negotiation
- Link detected

Step 3:
    ip -s link show eth0

Check:
- RX errors
- TX errors
- Drops
- Overruns
- Carrier errors

Step 4:
    sudo ethtool -S eth0

Check NIC-specific counters.

Step 5:
Check switch port:
- Speed
- Duplex
- CRC errors
- Drops
- Collisions
- Late collisions

Step 6:
Check physical layer:
    NIC
      ↓
    Cable
      ↓
    Patch panel
      ↓
    Switch port

Bad cable or connector can cause errors.


21. COMMON MISTAKES

Mistake 1:
"Half duplex means slow."

Correction:
Half duplex means both directions are possible but not simultaneously.
Speed and duplex are separate concepts.


Mistake 2:
"Full duplex means double speed."

Correction:
1 Gbps full duplex generally means:
- Up to 1 Gbps A → B
- Up to 1 Gbps B → A
simultaneously.

It does not automatically mean 2 Gbps in one direction.


Mistake 3:
"Half duplex means only one direction is possible."

Correction:
Both directions are possible.
Only simultaneous transmission is prohibited.


Mistake 4:
"Simplex means only one device exists."

Correction:
Two devices can exist.
Communication direction is simply one-way.


Mistake 5:
"Full duplex means no packet loss."

Correction:
Full duplex removes traditional collision problems on a full-duplex point-to-point link, but packet loss can still happen due to:
- Congestion
- Buffer overflow
- Hardware problems
- Cable problems
- CRC errors
- Queue drops
- Routing issues
- MTU problems


22. INTERVIEW QUESTIONS

Q1. What is Simplex?
A:
Simplex is one-way communication where data flows only from sender to receiver.

Q2. What is Half Duplex?
A:
Two-way communication where only one direction can transmit at a time.

Q3. What is Full Duplex?
A:
Two-way communication where both directions can transmit simultaneously.

Q4. Give examples.
A:
Simplex: traditional TV broadcast.
Half Duplex: walkie-talkie.
Full Duplex: telephone and modern switched Ethernet.

Q5. Why can collisions occur in half-duplex Ethernet?
A:
Because multiple devices may share the same medium and attempt simultaneous transmission.

Q6. What is CSMA/CD?
A:
Carrier Sense Multiple Access with Collision Detection. It was used to handle collisions in shared/half-duplex Ethernet.

Q7. Is CSMA/CD required for modern full-duplex Ethernet?
A:
No. Normal full-duplex switched Ethernet does not have the traditional shared-medium collision problem.

Q8. How do you check duplex in Linux?
A:
sudo ethtool eth0

Q9. What is duplex mismatch?
A:
A condition where two ends of an Ethernet link operate with incompatible duplex settings, causing performance and error problems.

Q10. Does full duplex double link speed?
A:
No. It allows simultaneous traffic in both directions. It does not automatically double the one-direction speed.

Q11. Is TCP the same as full duplex?
A:
No. TCP provides bidirectional transport communication, while duplex describes lower-level communication behavior.

Q12. Which OSI layers are mainly associated with duplex?
A:
Physical and Data Link aspects of the networking technology.
