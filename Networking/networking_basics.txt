============================================================
NETWORKING BASICS
============================================================

1. WHAT IS A NETWORK?
------------------------------------------------------------

A network is a collection of two or more devices connected
together so that they can communicate and exchange data or
share resources.

Examples:
- Laptop connected to Wi-Fi router
- Computers connected through a switch
- Servers connected inside a data center
- Cloud resources connected through a virtual network

Important:
A network is not necessarily the Internet.

Example:

Laptop ---- Switch ---- Printer

This is a network even if there is no Internet connection.


============================================================
2. WHAT IS NETWORKING?
============================================================

Networking is the process/field of designing, connecting,
configuring, operating, securing, and troubleshooting networks
so that devices and systems can communicate.

Simple distinction:

Network    = What exists
Networking = How communication is established and managed


============================================================
3. MAIN PURPOSE OF NETWORKING
============================================================

The fundamental purpose of networking is:

To allow information to move from one device/process to
another device/process.

Examples:
- Browser communicating with a web server
- Application communicating with a database
- Laptop communicating with a printer
- Kubernetes pods communicating with each other


============================================================

============================================================
5. NETWORK DEVICES
============================================================

Important network devices:

1. Switch
   - Connects devices within a local network.
   - Primarily forwards Ethernet frames based on MAC addresses.

2. Router
   - Connects different networks.
   - Forwards IP packets toward the appropriate destination/
     next hop.

3. Firewall
   - Controls network traffic according to security rules.
   - Can allow or deny traffic based on IP, port, protocol,
     direction, etc.

4. Load Balancer
   - Distributes traffic across multiple backend servers.


============================================================
6. END DEVICES
============================================================

Devices that generate or consume network data are called

Examples:
- Laptop

- Mobile

- Printer

============================================================
7. ADDRESSING
============================================================

Networks need addressing so that data can reach the correct
destination.

Important addressing concepts:

MAC Address
- Used at the data-link layer.
- Identifies a network interface on a local network.

IP Address
- Logical network address.
- Used for communication and routing between networks.

Port Number
- Identifies a service/application endpoint on a host.

Domain Name
- Human-friendly name that can be resolved to an IP address.

Example:

10.0.0.10:443

10.0.0.10 = IP address
443        = port


============================================================
8. NETWORK VS INTERNET
============================================================

Network:
A connected collection of devices/systems.

Internet:
A global system of interconnected networks.

Important statement:

Every Internet connection involves networking,
but every network is not the Internet.


============================================================
9. COMMON NETWORK TYPES
============================================================

LAN
- Local Area Network
- Usually limited to a home, office, building, etc.

WAN
- Wide Area Network
- Connects networks over larger geographic areas.

Internet
- Global interconnected network of networks.

Intranet
- Private/internal organizational network.

19. DEVOPS TROUBLESHOOTING MINDSET
============================================================

If an application cannot connect to another service, ask:

1. What is the destination?
2. Is the hostname resolving correctly?
3. What is the destination IP?
4. Is a route available?
5. Is the destination port reachable?
6. Is a firewall/security rule blocking traffic?
7. Is the destination service actually running?
8. Is the service listening on the expected port?
9. Is the correct protocol being used?
10. Is the application configuration correct?

This mindset is very useful for production
DevOps troubleshooting.
