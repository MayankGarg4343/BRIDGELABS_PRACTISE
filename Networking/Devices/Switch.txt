TOPIC: SWITCH — Full Notes


1. DEFINITION

Switch ek networking device hai jo primarily OSI Layer 2 (Data Link Layer)
par operate karta hai.

Iska main kaam Ethernet Frames ko destination MAC address ke basis par
appropriate port/interface par forward karna hai.

Simple definition:

Switch ek intelligent Layer-2 device hai jo multiple devices ko LAN mein
connect karta hai aur MAC addresses ke basis par traffic ko selectively
forward karta hai.


2. OSI LAYER

Traditional Ethernet Switch:
- Layer 2
- Data Link Layer

Important concepts:
- Ethernet Frame
- MAC Address
- MAC Address Table
- Forwarding
- Filtering
- Flooding
- VLAN
- STP

Note:
Layer-3 switches bhi exist karte hain jo Layer-2 switching ke saath
Layer-3 routing bhi perform kar sakte hain.


3. SIMPLE MENTAL MODEL

Switch ko ek smart courier sorting center samjho.

Courier ke paas mapping hai:

Device A → Port 1
Device B → Port 2
Device C → Port 3

Agar destination B hai:

Incoming Frame
      ↓
Destination B
      ↓
MAC Table
      ↓
Port 2
      ↓
Forward


4. BASIC SWITCH DIAGRAM

5. SWITCH KA MAIN PURPOSE

Switch:

- Multiple devices ko LAN mein connect karta hai.
- Ethernet frames ko forward karta hai.
- MAC addresses learn karta hai.
- Unnecessary unicast traffic ko filter karta hai.
- Collision domains ko separate karta hai.
- VLAN-based Layer-2 segmentation provide kar sakta hai.
- Redundant Layer-2 topology mein STP use kar sakta hai.


6. SWITCH VS HUB

Hub:

PC1 → Hub → PC2
          → PC3
          → PC4

Hub Layer 1 par signal ko repeat karta hai.

Switch:

PC1 → Switch → PC2

Switch destination MAC ke basis par known unicast ko correct port par
forward kar sakta hai.

Main difference:

Hub:
- Layer 1
- Signal repetition
- No MAC learning
- Shared medium

Switch:
- Layer 2
- Frame forwarding
- MAC learning
- Selective forwarding


7. SWITCH VS BRIDGE

Bridge:
- Layer 2
- MAC-based forwarding
- Usually fewer ports historically

Switch:
- Layer 2
- MAC-based forwarding
- Many ports
- High-speed hardware forwarding

Important:

A modern Ethernet switch ko essentially a high-performance
multiport bridge samjha ja sakta hai.


8. SWITCH KE FOUR FUNDAMENTAL OPERATIONS

1. Learning
2. Forwarding
3. Filtering
4. Flooding


9. MAC ADDRESS TABLE

Switch MAC address table maintain karta hai.

Example:

MAC Address              Port

AA:AA:AA:AA:AA:01        Port 1
BB:BB:BB:BB:BB:02        Port 2
CC:CC:CC:CC:CC:03        Port 3


10. MAC LEARNING

Switch incoming Ethernet frame ke Source MAC address ko dekhta hai.

Example:

Source MAC:
AA:AA:AA:AA:AA:01

Incoming Port:
Port 1

Switch learns:

AA:AA:AA:AA:AA:01 → Port 1

Golden rule:

Source MAC → Learning


11. DESTINATION MAC

Destination MAC forwarding decision ke liye use hota hai.

Golden rule:

Source MAC:
Learning ke liye.

Destination MAC:
Forwarding/filtering decision ke liye.


12. COMPLETE FRAME PROCESSING

Frame switch par aaya.

Step 1:
Frame receive karo.

Step 2:
Source MAC learn/update karo.

Step 3:
Destination MAC dekho.

Step 4:
MAC address table mein lookup karo.

Step 5:
Decision:

- Known destination → Forward
- Same incoming port → Filter
- Unknown destination → Flood
- Broadcast → Flood


13. KNOWN UNICAST

Example:

PC1:
MAC = AAA

PC2:
MAC = BBB

Switch table:

AAA → Port 1
BBB → Port 2

PC1 sends:

Source MAC = AAA
Destination MAC = BBB

Switch:

AAA → Port 1
BBB → Port 2

Therefore:

PC1
 ↓
Switch
 ↓
Port 2
 ↓
PC2

PC3 ko frame normally forward nahi hoga.


14. FILTERING

Filtering means frame ko unnecessary port par forward na karna.

Example:

PC1 and PC2 same switch port/Layer-2 segment context mein hain.

Destination MAC already same incoming interface par located hai.

Switch:

Do not forward frame to another port.

This is filtering.


15. FORWARDING

If destination MAC kisi different port par known hai:

Example:

PC1 → PC3

MAC table:

PC3 MAC → Port 3

Switch:

Port 1
  ↓
Switch
  ↓
Port 3
  ↓
PC3


16. UNKNOWN UNICAST

Example:

Destination:
DD:DD:DD:DD:DD:04

MAC table:

AAA → Port 1
BBB → Port 2
CCC → Port 3

DD unknown.

Switch generally unknown-unicast flooding karta hai.

Frame:

Port 1
 ↓
Switch
 ↓ ↓
Port 2 Port 3


17. BROADCAST

18. ARP AND SWITCH

Suppose:

PC1:
192.168.1.10

PC2:
192.168.1.20

PC1 ko PC2 ka MAC nahi pata.

PC1 ARP request send karta hai:

"Who has 192.168.1.20?"

Destination MAC:

FF:FF:FF:FF:FF:FF

Switch broadcast ko flood karta hai.

PC2 ARP reply karta hai:

"192.168.1.20 is at BB:BB:BB:BB:BB:02"

Ab PC1 ke paas PC2 ka MAC hai.

Future traffic:

PC1
 ↓
Switch
 ↓
PC2


19. SWITCH AND ARP

ARP exchange ke time switch MAC learning bhi karta hai.

ARP request:

Source MAC = PC1
Incoming Port = Port 1

Switch learns:

PC1 MAC → Port 1

ARP reply:

Source MAC = PC2
Incoming Port = Port 2

Switch learns:

PC2 MAC → Port 2


20. MAC TABLE AGING

MAC entries permanently nahi rehti.

Agar device long time tak traffic generate nahi karta,
entry eventually age out ho sakti hai.

Reason:

- Devices move kar sakte hain.
- Ports change ho sakte hain.
- Old information stale ho sakti hai.


21. MAC ADDRESS MOVE

Initially:

AAA → Port 1

Later same MAC Port 5 se frame send karta hai.

Switch update kar sakta hai:

AAA → Port 5

Ye normal MAC learning behavior hai.


22. MAC FLAPPING

Example:

AAA → Port 1
AAA → Port 5
AAA → Port 1
AAA → Port 5

Same MAC repeatedly different ports par appear kar raha hai.

Isse MAC Flapping kehte hain.

Possible causes:

- Layer-2 loop
- Redundant link problem
- Misconfigured bridge
- Virtualization/networking issue
- Network topology problem


23. COLLISION DOMAIN

Switch ports traditionally separate collision domains.

Example:

Port 1 → Collision Domain 1
Port 2 → Collision Domain 2
Port 3 → Collision Domain 3

Modern Ethernet normally full-duplex hota hai, so normal operation mein
collisions nahi hoti.


24. FULL DUPLEX

67. INTERVIEW QUESTIONS

Q: What is a switch?

A:
A Layer-2 networking device that forwards Ethernet frames based on
destination MAC addresses.

Q: Which OSI layer does a switch operate at?

A:
Layer 2 for traditional Ethernet switching.

Q: What is a MAC address table?

A:
A mapping of learned MAC addresses to switch ports/interfaces.

Q: How does a switch learn MAC addresses?

A:
By examining source MAC addresses of incoming frames.

Q: What is the role of destination MAC?

A:
It is used to determine forwarding/filtering behavior.

Q: What happens when destination MAC is known?

A:
Frame is forwarded to the associated port.

Q: What happens when destination MAC is unknown?

A:
Unknown-unicast flooding occurs within the relevant VLAN/broadcast domain.

Q: What happens with broadcast?

A:
Broadcast is flooded within the same VLAN/broadcast domain.

Q: Does a switch separate collision domains?

A:
Yes, traditional switch ports create separate collision domains.

Q: Does a switch separate broadcast domains?

A:
Not by itself. VLANs create separate broadcast domains.

Q: What is MAC flapping?

A:
Same MAC address repeatedly appearing on different switch ports.

Q: What can cause MAC flapping?

A:
Often Layer-2 loops or topology/configuration issues.

Q: What is STP?

A:
Spanning Tree Protocol, used to prevent Layer-2 loops while maintaining
redundant paths.

Q: What is VLAN?

A:
Virtual Layer-2 segmentation that creates separate broadcast domains.

Q: Access port vs trunk?

A:
Access port typically carries one VLAN for an end device.
Trunk carries multiple VLANs.

Q: What is 802.1Q?

A:
IEEE VLAN tagging mechanism.

Q: What is FCS?

A:
Frame Check Sequence, used for Ethernet frame integrity/error detection.

Q: What is store-and-forward switching?

A:
Switch receives the complete frame, checks it, then forwards it.

Q: What is a Layer-3 switch?

A:
A switch capable of performing Layer-3 routing in addition to Layer-2
switching.

Q: Why does an Internet-bound host use the gateway's MAC?

A:
Because the gateway is the local Layer-2 next hop, while the remote
Internet server is outside the local Layer-2 network.

73. ONE-LINE FINAL SUMMARY

A switch is primarily a Layer-2 networking device that learns source MAC
addresses, uses the destination MAC to make forwarding decisions, forwards
known unicast frames to the correct port, filters unnecessary traffic,
floods unknown/broadcast traffic within the relevant VLAN, and provides the
foundation for modern LAN switching, VLAN segmentation, and many
virtualization/container networking designs.
